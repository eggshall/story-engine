## 0. 结论速览 (TL;DR)

**一句话结论:** 古籍原文本身 100% 公版、可自由「参考/默写/化用」；真正的版权雷区在**今人整理本（点校本/校注本/白话译本）**。数据源方面，国内直连可用且质量最高的是 **ctext.org（API 可拉全文）+ 书格（高清扫描 PDF）+ 识典古籍（AI 整理平台）**；维基文库、Internet Archive、中华古籍资源库（read.nlc.cn）在裸连下均超时，需代理。工具链上，**通古大模型（TongGu-7B）+ OpenCC + CBDB/CHGIS** 是一套可直接落地的开源组合，但模型/代码托管在 HuggingFace/GitHub（裸连超时）。

## 1. 中文古籍/史料数据源

### 1.1 ctext.org 中国哲学书电子化计划 ⭐ 首选
- **官网**: https://ctext.org/ （中文 https://ctext.org/zhs）
- **内容范围**: 先秦两汉至明清传世文献 3 万+ 部、约 50 亿字，自称「历代中文文献资料库最大者」。经史子集、先秦诸子、二十五史核心篇目、出土文献（清华简等）部分收录。
- **获取方式**:
  - 网页逐篇阅读（繁/简切换、英文翻译）。
  - **JSON API**: https://api.ctext.org/ （函数如 `getlink` / `readlink` / `getstatus`；文档 https://ctext.org/tools/api/zhs ）。CORS 友好，适合前端。
  - **Python 客户端**: `pip install ctext`（官方）。
  - 全文导出插件（「全文输出」，输出原典全文纯文本）。
- **登录/订阅**: 网页阅读无需登录；API 有分层限流——未登录者仅能读少量，登录账户更多，**订阅机构（IP 注册）可读全文**（https://ctext.org/tools/subscribe ）。
- **编码/格式**: UTF-8 纯文本；繁/简两种显示；无竖排；**非扫描影像**（文本已数字化）。
- **开放授权**: 版权保留（©2006–2026），引用须加链接；**严禁用自动下载软件抓取大量网页，违者封 IP**。→ 对小说「参考/用典」友好，但**禁止批量爬取**，需要全文批量应走订阅或逐篇合法获取。
- **直连**: ✅ 200。API ✅ 200。
- **评级**: 数据源 A 级（文本质量高、API 可用、直连稳定），但批量抓取受限。

- **官网**: https://zh.wikisource.org/

## 2. 版权边界（重点）

### 2.1 基本框架
- **古籍原文（公版）**: 作者早已去世远超保护期（中国《著作权法》保护期为作者终生 + 死亡后 50 年，人身权永久；伯尔尼公约亦 50 年）。先秦至清代的古籍原文**早已进入公有领域**，任何人可自由复制、引用、改写、默写、化用，无需授权。
- **今人整理本（点校本/校注本/标点本/白话译本）**: 属于《著作权法》规定的**演绎/整理作品**——「改编、翻译、注释、整理已有作品而产生的作品，其著作权由整理人享有」。点校（校勘、标点、分段、订误）体现独创性智力劳动，受著作权保护。

### 2.2 关键判例：中华书局诉汉王 / 国学网案
- 北京市高级人民法院 **(2005)高民终字第442号** 判决确认中华书局对**点校本「二十四史」及《清史稿》**享有著作权（新中国最大古籍整理工程，百余专家数十年成果）。
- 侵权判定核心：**「我改你也改、我错你也错」**——若他人版本与点校本在校勘、标点、异文处理上高度一致（包括复制其错讹），即构成**实质性相似**，判侵权。
- 反方（国学网尹小林）观点：标点是有限表达、趋同性强，不应垄断；但法院采信了「有独创性整理成果」的立场。→ **实务结论：点校本的标点与校勘成果受保护，不能照搬。**

### 2.3 对小说写作的可用性结论
| 行为 | 法律风险 | 结论 |
|---|---|---|
| 引用/化用/默写**古籍原文**（公版） | 无 | ✅ 可自由用 |
| 参考公版底本**自行重新标点/白话改写** | 无 | ✅ 可（但成本高、易与点校本趋同） |
| 大量照搬**中华书局点校本**的标点/校勘文字 | 高 | ❌ 侵权 |
| 复制**今人白话译文**（各译本） | 高 | ❌ 侵权（译文是独立作品） |
| 少量引用点校本原文 + 注明出处 | 低（合理使用） | ⚠️ 谨慎、注明来源 |
| 「默写」历史文献作为小说情节素材 | 视内容 | ✅ 原文公版安全；但别复制今人译文/整理成果 |
| 商用发布含点校本长段原文 | 高 | ❌ 需授权 |

**行业惯例**: 历史小说用典、化用公版原文为普遍且合法做法；引文超过「少量合理引用」范围时需注明来源并控制篇幅；**切勿把点校本/白话译本的文字直接搬进作品**。对 AI 生成系统：**训练/检索语料应优先用公版底本（ctext 原文、维基文库原文、Gutenberg），避免把受保护的点校本全文塞进可商用的产出链路。**

### 2.4 数据库本身的授权（拉取时需注意）
- **ctext.org**: 版权保留 + 禁批量抓取（见 §1.1）。
- **CBDB**: CC BY-NC-SA 4.0（**非商业**、相同方式共享）。
- **通古 ACCN-INS 训练数据**: 仅限非商业研究，需填申请表（见 §3.2）。
- **书格**: 公版 + 不声明新版权，最干净。
- **维基文库**: PD + CC BY-SA 3.0（SA 要求衍生同授权，商用可但需同许可）。

## 4. 从「史料」到「小说可用设定」的成熟做法

### 4.1 结构化模板（可直接用于 story-engine 数据层）
建议按以下五类「卡片」结构拆解史料，每张卡片带**出处（书/卷/页 + 底本来源）**：

1. **人物志卡片**（对接 CBDB 字段）: 姓名/字号/生卒年/籍贯（古今地名对照，对接 CHGIS）/官职履历（任职年份 + 官名 + 别名）/亲属与婚姻/交游与师承/史源出处。
2. **年表卡片**: 事件年-月-日 / 人物 / 地点 / 性质 / 史源（多书互证）。
3. **典章制度卡片**: 制度名 / 朝代 / 机构沿革 / 职官品级 / 服饰车舆 / 律法 / 史源（如《通典》《文献通考》《职官志》）。
4. **名物器物卡片**: 器物名 / 时代 / 形制 / 用途 / 出土地 / 文献与图像出处（书格/国图影像）。
5. **典故/成句卡片**: 典故原文 / 出处 / 本义 / 后世用义 / 可化用场景。

> 传统史学家的「史料卡片法」（严耕望《治史三书》强调的抄卡片、做长编）正是此法的原型；现代工具用 Obsidian/Notion + 双向链接 + 标签可落地。

### 4.2 公开高质量案例
- **马伯庸《显微镜下的大明》**: 直接以明代徽州府诉讼档案（丝绢案等 6 个档案故事）为底本，先做史料考据再「非虚构式」还原——示范了「一份档案 → 一个故事」的史料驱动写作（公开报道/作品序言所述，未逐条核对原档案）。
- **马伯庸《长安十二时辰》/《两京十五日》**: 以唐长安城考古复原（里坊布局、西市）与明代漕运/运河制度考据搭建世界观——示范「地理/制度史料 → 场景与情节框架」。
- **AI 辅助实践**: 通古大模型官方定位即「古籍数字化 + 古籍问答/赏析」；社区常见做法是 **RAG（检索增强）+ 古籍库 + 辞书** 来抑制「AI 瞎编典故」幻觉——与 story-engine 拟写/用典需求直接对应。

### 4.3 落地建议（针对 story-engine）
1. **文本层**: 以 ctext（API 逐篇）+ 维基文库（代理 + MediaWiki API）+ Gutenberg 作为公版文本主源，写入本地索引；禁止批量爬 ctext。
2. **影像/底本层**: 书格 PDF + 国图/NDL 影像用于「核对原貌 + 版式/插图」，OCR 后并入文本层。
3. **结构化知识层**: CBDB（人物/职官）+ CHGIS（地名/政区）导入图数据库或 SQLite，供「人物志/年表/地理设定」生成。
4. **处理管线**: OpenCC（繁简/异体归一）→ 通古大模型（句读 + 文白双向 + 典故问答，经 ModelScope 国内拉取）→ 结构化抽卡。
5. **合规护栏**: 语料仅用公版底本；商用产物中不得出现点校本/今译本的照搬文字；输出引文标注出处（公版）。
