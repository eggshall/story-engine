# R5 · 当下热点素材接入方案(国内可直连源) + 借古喻今写法合规边界

> 调研日期: 2026-10-11 · 环境: WSL (国内网络, 无 VPN 代理)
> 用途: story-engine 写作系统在生成中文长篇小说时, 注入"当下热点"作为借古喻今的素材源, 并规避合规风险。
> 实测方法: 单条 `curl` 直连 (未写文件、未走代理), 结果如实记录; 拉不到的如实标注"拉不到"。

### 1. 百度热搜 (推荐首选: 无鉴权 + 官方 JSON + 快)

- **JSON API**: `https://top.baidu.com/api/board?platform=wise&tab=realtime`
- **HTML 页**: `https://top.baidu.com/board?tab=realtime`
- **鉴权/签名**: 无。仅建议带浏览器 UA。
- **字段结构** (实测返回):
  ```json
  {"success":true,"data":{"cards":[{"component":"tabTextList","content":[
    {"isTop":true,"word":"总书记同卫生健康工作者的故事","url":"https://m.baidu.com/s?word=...","index":0},
    {"isTop":false,"index":1,"word":"部分大闸蟹跌出'地板价'","hotTag":"0"},
    ...
  ]}]}}
  ```
  核心字段: `word`(热搜词) / `url`(搜索落地页) / `isTop`(置顶) / `index`(排名) / `hotTag`(热度标签, "0"~"爆"等)。
- **限流/反爬**: 弱。官方接口, 但 `tab` 参数可选 `realtime`/`novel`/`movie`/`teleplay`/`car` 等垂直榜。
- **实测**: 200, 94ms, ~23KB。✅ 稳定可直连。

### 2. 知乎热榜 (标题含完整议题描述, 最适合"议题抽取")

- **JSON API(无需登录)**: `https://api.zhihu.com/topstory/hot-list?limit=50&desktop=true`
- **⚠️ 老接口已废**: `https://www.zhihu.com/api/v3/feed/topstory/hot-lists/total` → 实测 **401**(需登录 cookie)。
- **鉴权/签名**: v4 接口 `api.zhihu.com/topstory/hot-list` 实测**无需任何鉴权**, 直接返回。
- **字段结构** (实测):
  ```json
  {"data":[
    {"type":"hot_list_feed",
     "target":{"id":2092513467722719411,
       "title":"沙特利雅得机场遭袭, 造成 12 人死亡 309 人受伤…",
       "url":"https://api.zhihu.com/questions/...",
       "answer_count":377,"follower_count":925,"created":1791674087,
       "excerpt":"…","bound_topic_ids":[337,3853]},
     "detail_text":"3732 万热度","trend":0,"debut":false,
     "card_label":{"type":"boiling"}  // boiling=沸 hot=热 new=新
    }],
   "paging":{...},"display_num":15}
  ```
- **优点**: `title` 是**带观点的完整问句** (如"如何看待给大模型投毒被字节索赔800万的前实习生开启创业…"), 比微博的短词更适合抽取主题; `excerpt` 给背景; `answer_count`/`follower_count` 是强度信号。
- **限流/反爬**: 中低。无签名, 但高频抓取可能触发风控, 建议 60s+ 间隔。
- **实测**: 200, 258ms, ~52KB(limit=10)。✅

### 3. 抖音热榜 (字段最干净, 纯词条+数值热度)

- **JSON API**: `https://www.iesdouyin.com/web/api/v2/hotsearch/billboard/word/`
- **鉴权/签名**: 无。
- **字段结构** (实测):
  ```json
  {"status_code":0,"active_time":"2026-10-11 15:59:27",
   "word_list":[{"word":"周启豪无缘WTT男单决赛","hot_value":12103802,"label":1},
                {"word":"沙特利雅得机场遇袭","hot_value":11120474,"label":3}, ...]}
  ```
  核心字段: `word`(词条) / `hot_value`(数值热度, 可直接做排序/衰减) / `label`(标签: 1=热/3=新/9=挑战/5=影视 等, 映射不官方, 建议仅当参考)。
- **限流/反爬**: 弱。稳定直连, 适合高频轮询。
- **实测**: 200, 255ms, ~3.8KB。✅

### 4. 腾讯新闻热榜 (带全文摘要, 信息量最大)

- **JSON API**: `https://r.inews.qq.com/gw/event/hot_ranking_list?page_size=50`
- **鉴权/签名**: 无。
- **字段结构** (实测):
  ```json
  {"ret":0,"idlist":[{"ids_hash":"...","newslist":[
    {"id":"20261010A0B7ZM00","title":"我们的长征路丨从湘江古渡到'长征绿道'",
     "abstract":"…(数百字摘要)…","url":"https://view.inews.qq.com/a/...",
     "hotEvent":{"id":"...","ranking":1,"title":"...","hotScore":1336041,"is_top":1},
     "readCount":18493,"time":"2026-10-10 19:37:40","timestamp":1791632260}
  ]}]}
  ```
  核心字段: `title` / `abstract`(长摘要, 可直接喂给 LLM) / `hotEvent.hotScore`(数值热度) / `hotEvent.ranking` / `url` / `readCount` / `timestamp` / `card.chlname`(来源媒体)。
- **限流/反爬**: 弱。返回体较大(50 条约 470KB), 建议 `page_size` 取 20~30 减小载荷。
- **实测**: 200, 162ms, ~476KB(page_size=50)。✅

### 5. B站热门排行 (视频/番剧热点的补充源)

- **JSON API**: `https://api.bilibili.com/x/web-interface/ranking/v2?rid=0&type=all`
- **鉴权/签名**: 无(部分接口需 buvid cookie, 排行接口无需)。
- **字段**: `data.list[].{title, owner.name, bvid, play, favorite, comment, ...}`; `rid` 分区(0=全站)。
- **限流/反爬**: 弱, 但有 UA 风控, 建议带浏览器 UA。
- **实测**: 200, 246ms, ~167KB。✅

### 6. 今日头条热榜 (HTML 内嵌 JSON, 需解析)

- **HTML 页**: `https://www.toutiao.com/hot-event/hot-board/?origin=toutiao_pc`
- **鉴权**: 无, 但页面 SSR, 数据在 `window.__INITIAL_STATE__` 或内嵌 `<script>` 中, 需正则/JSON 提取。
- **实测**: 200, 291ms, ~128KB。✅ 可直连, 解析成本高于纯 JSON 接口。

### 7. 网易新闻热榜 (HTML)

- **HTML 页**: `https://news.163.com/special/0001386F/rank_whole.html`
- **实测**: 200, 397ms, ~157KB。✅ 数据在 HTML 中, 需解析。

### 8. 雪球热股 (金融热点; API 需 cookie)

- **首页**: `https://xueqiu.com/` → 实测 200, 371ms。
- **⚠️ API**: `https://stock.xueqiu.com/v5/stock/hot_stock/list.json` 等需先访问首页拿 `xq_a_token` cookie, 且有签名。仅作金融题材热点补充, 不建议首期接入。
- **实测**: 首页 200 ✅; API 未带 cookie 时 401。

### 9. Tophub 今日热榜 (多平台聚合, 一页看全)

- **HTML 页**: `https://tophub.today/`
- **鉴权**: 无。
- **优点**: 一个页面聚合微博/知乎/抖音/百度/头条/贴吧等几十个榜单; 有 `https://tophub.today/n/{节点}` 单榜页。
- **⚠️ 缺点**: 实测**响应慢(~8s, 503KB)**, 且有 JS 渲染依赖, 脚本抓取需处理。
- **实测**: 200, 但 time=8.0s(触达 max-time 边界), 大小 503KB。✅ 能连, 但慢。

### 10. NewsNow (开源自部署聚合器, 官方演示可直连)

- **GitHub 仓库**: `https://github.com/ourongxing/newsnow` — ⚠️ 本 WSL 环境实测 **000 超时**(github.com 直连不通)。
- **官方演示部署(国内可直连)**: `https://newsnow.busiyi.world/` → 200 ✅
- **JSON API(聚合微博/知乎/百度/头条等)**: `https://newsnow.busiyi.world/api/s?id=weibo` → 200 ✅, 15KB。
  - `id` 参数取 `weibo`/`zhihu`/`baidu`/`toutiao` 等; 返回该平台实时热榜 JSON。
- **自部署**: Docker 一键部署, 数据源可配, 是"微博 403 不可直连"时的**最稳替代**。
- **实测**: 首页 200(0.65s) / API 200(0.90s)。✅

### 11. RSSHub (通用路由, 官方被墙但镜像可用)

- **官方**: `https://rsshub.app/` → 实测 **000 超时**(被墙)。
- **公共镜像(国内可直连)**: `https://rsshub.rssforever.com/` → 200 ✅
- **路由**: 如 `/weibo/search/hot`(微博热搜)、`/zhihu/hotlist`、`/bilibili/ranking/0/0/3/1` 等, 返回 RSS 2.0, 加 `.json` 后缀可得 JSON。
- **⚠️ 注意**: 公共镜像稳定性差、易被限流(实测 `/weibo/search/hot` 在 rssforever 上返回 **503**); 生产建议**自部署** RSSHub 或 Docker 起本地实例。
- **实测**: 镜像首页 200 ✅; 微博热搜路由 503 ⚠️。

### 12. 微博热搜 (官方接口需登录, 直连受限)

- `https://weibo.com/ajax/side/hotSearch` → 实测 **403**(需登录 cookie)
- `https://weibo.com/ajax/statuses/hot_band` → 实测 **403**
- `https://m.weibo.cn/api/container/getIndex?containerid=106003type=25...` → 实测 **302**(跳登录)
- **结论**: 微博官方接口无 cookie 不可用。**替代路径**: ① NewsNow 演示 API(`/api/s?id=weibo`) ② RSSHub 镜像/自建 ③ 自维护微博小号 cookie(易失效, 不推荐)。建议**不直接依赖微博源**, 用聚合器兜底。

## 二、借古喻今/历史映射现实的合规边界

> ⚠️ 本节只陈述**公开规则与已发生的处理惯例**, 不含任何规避审核的建议。来源均为公开编辑指南、官方文件、作者公开访谈。

### 2.1 明确红线(有公开编辑指南原文支撑)

来源: 飞卢小说网公开编辑入库指南(经"违禁词检测"工具站转载, 2025-01); 歪脑(wainao.me) 2023 对网文作者审查生态的长篇访谈。

1. **近现代中国政治事件与人物(1919—2050)不写**。编辑指南原文: "1919-2050 年的中国的政治事件、著名政治人物及其子女, 都不要写为好"。
2. **"换名影射"依然违规**。原文: "虽然号称是虚拟了背景, 但是过于明显的违禁内容都不要写。比如 Z 国、T 岛、X 藏、J 国…就算你换成中华、宝岛、倭国, 要违禁一样是违禁的。" —— 即**借古喻今的"喻"若指向敏感现实议题, 不会因为改朝代/改地名而豁免**。
3. **中国特色政治/军事称谓作为背景要慎重**(主席、指导员等)。架空/穿越文里如果出现这类强烈现实指涉, 编辑会要求解释、修改后才入库。
4. **色情与低俗主题一律不收**, 性器官/性过程/性心理描写禁止, 擦边不鼓励。
5. **抄袭零容忍**(与热点素材工程直接相关: 抓取热榜用于创作≠照搬他人文章/标题, 需转写)。

### 2.2 "借古讽今"与"借古喻今"的本质区别(合规分水岭)

- 语文教学界对两者有明确区分(香港 DSE 中文教材公开讲义): **"借古讽今" = 借古人古事**讽刺批判**现实 → 高风险**; **"借古喻今" = 借古人古事**比喻**现实 → 中性/正面**。
- 判例: 张抗抗《国魂》中, 父亲因发表一部历史人物传记、赞颂一位"含冤而死的兵部尚书", 被认定为"借古讽今"—— 说明**对历史人物的褒贬一旦映射现实当权者/现实事件, 即越界**。
- **工程含义**: story-engine 的"映射"应锁定在**比喻/类比层(结构相似: 供给过剩→盐粮价跌→官府平准)**, 而非**讽喻/批判层(立场相似: 影射当下政治人物/事件/制度)**。前者是创作技法, 后者是影射批判。

### 2.3 广电/总局对"历史题材"的具体红线(公开"内部分享"文件)

来源: 《总局关于影视题材拍摄内容的内部分享》文件(2018 流传, 流媒体网 lmtw.com 全文收录; 知乎专栏转载)。虽针对影视, 但网文平台普遍参照同类逻辑, 与飞卢编辑指南互相印证, 是**最具体的一手规则清单**。

**历史类红线:**
1. **正史不可颠覆性改编, 野史可改**(《三国志》不可改、《三国演义》可改)。
2. **不能违背已有定论的人/事/物**(司马懿的主要成就须尊重正史; 真实历史无记载的小人物可自由演绎)。
3. **不能触碰历史禁忌**: 汉唐时期疆土扩张避免提及; 夜郎、楼兰等古地不能称"国"; **岳飞不称"民族英雄", 大金也是中国的一部分**; 左宗棠(曾代表清政府镇压回族起义)不宜涉及; **美化民国、北洋政府(李鸿章、袁世凯)要控制**。
4. **不能渲染腐朽的历史观/价值观**(《甄嬛传》《如懿传》《琅琊榜》的"后宫阴谋"被点名, 被认为非中华传统文化、缺乏正面性)。
5. **架空要彻底**: 虚构世界需完全架空, 服化道不能有明显朝代风格(如《冰与火之歌》)。

**民族宗教类红线:**
1. 符合宗教法规与少数民族条例。
2. 作品不宣传宗教, 尊重宗教文化(反面例《不负如来不负卿》违背佛教断情欲原则)。
3. 尊重少数民族习俗, 严格控制服化道, 避免文字/服装/台词引发民族矛盾。

**题材类红线(与借古喻今直接相关):**
1. **国事勿要妄议, 规避社会制度、国家现状、大的发展形势**。
2. 多写平凡小人物, 减少历史名人改编。
3. 破除封建迷信(网络电影下架原因前三有"涉嫌封建迷信")。
4. 穿越/架空人物要有正能量, 不改变历史大格局, 对时代有正面作用。
5. 现实/历史题材"三观正", 追求财富走正当手段, 不炫富。

### 2.4 "影射现实"的现实风险与平台执行(客观陈述)

- **平台执法案例**: 2020 年晋江文学城因涉淫秽色情被查处、关停"东方架空""东方幻想"栏目并停更原创分站 15 天; 阅文起点因"导向错误、低俗色情"被网信办约谈, "都市-异术超能""女生网-N次元"栏目停更 7 天。—— 说明平台执行是**频道/栏目级关停**, 后果不只在单书。
- **影视判例(可映射到小说题材)**: 《霸王别姬》(文革叙事消极)公映两天被禁;《鬼子来了》("丑化中国百姓、未充分暴露日军侵略本质")被禁;《天浴》《蓝风筝》(文革题材)禁; 美化达赖/西藏题材(《西藏七年》《达赖的一生》)禁; 《活着》(对政治运动嬉笑怒骂式批判)禁。—— 共同指向: **对特定历史时段/政治运动的负面化、批判化表达是硬红线**。
- **编辑一线口径**(起点编辑星河 B站公开视频; 飞卢编辑指南): 审核**结合上下文判断"现实指向"**, 不只查关键词; 书名/章节名/简介是审核重点; 换名影射(Z国/T岛/X藏/J国)依然违规。
- **正向示范**: 国家新闻出版署 2021 "优秀现实题材和历史题材网络文学出版工程"入选《天圣令》(蒋胜男)、《长乐里》(骁骑校)等, 说明**历史题材写家国、民生、奋斗、法治是受鼓励的**——借古喻今落脚在正面价值, 有官方认可空间。

### 2.5 给 story-engine 的工程化结论(合规设计原则, 非规避建议)

- **注入"议题骨架"而非"立场"**: 抽取"大闸蟹跌价/汽车测试乱象/新能源产业"等**社会/经济/民生/科技议题**做历史类比 = 安全区; 抽取**政治运动、民族冲突、宗教、涉军、疆土、民国/北洋**等议题并映射 = 高危区。
- **内置议题分级过滤器**: 热榜词条按敏感度分级(民生/经济/科技/职场/情感/娱乐 = 可映射; 政治/民族/宗教/涉军/近现代史 = 不映射或仅作背景)。这是合规护栏, 不是规避审核。
- **正面价值收束**: 家国、法治、奋斗、真善美; 与官方鼓励方向一致。
- **历史映射纪律**: 映射到**结构类比**(供给过剩→盐粮价跌→官府平准), 不映射到**人物/政权/国体影射**; 架空要彻底, 不出现强烈现实政治指涉称谓(主席/指导员等)。

## 三、从"热点"到"写作素材"的成熟做法

### 3.1 公开可参考的流程/方法论

1. **媒体特稿的"由古及今"专栏**: 传统媒体与深度报道中,"以史鉴今"是成熟体裁, 常规路径是 **今日议题 → 历史同类事件 → 机制对比 → 现实结论**。
2. **网文历史题材创作论**: 中国社科院文学所论文《考据、推演、抒情: 论近年网络历史小说"老白文"三调(2018—2023)》总结历史类网文的三种手法——**考据(史实底座)/推演(架空假设)/抒情(价值表达)**, 对应"借古喻今"的三个层次: 越接近"推演+抒情"越安全, 越刻意"考据式影射现实"越敏感。
3. **月关(China Daily 访谈)**: 穿越历史小说的核心是**把现代议题放进古代制度环境里重新求解**, 而非直接喊话现实。
4. **王夫之《读通鉴论》对"以史为鉴"的经典定义**(京报网引): "设身于古之时势, 为己之所躬逢; 研虑于古之谋为, 为己之所身任……取古人宗社之安危, 代为之忧患, 而己之去危以即安者在矣。" —— 这是"借古喻今"的方法论内核: **把"今之议题"代入"古之时势"重新推演, 落脚在"今之兴利除害"**。

### 3.2 热点→主题→历史类比→冲突设计的流水线(建议工程化)

1. **热点采集**: 用第一节的多源聚合(知乎 title + 抖音 hot_value + 腾讯 abstract)。
2. **主题抽取**: 对词条/标题做 LLM 抽取, 得到"议题 + 冲突双方 + 争议点"三元组(例: "大闸蟹跌出地板价"→ 议题=农产品价格/供给过剩, 冲突=养殖户 vs 市场, 争议=丰产不丰收)。
3. **议题分级**: 按 2.4 的过滤器过滤掉敏感议题, 保留民生/经济/科技/职场/情感等安全域。
4. **历史类比映射**: 用"结构类比"而非"人物影射"——把"供给过剩价格崩盘"映射为"古代某地盐/粮/绢丰收价跌、商贾囤积、官府平准"。
5. **冲突设计**: 把现代争议点转化为古代冲突(官府平准 vs 商人囤积 vs 小农破产), 落点在正面价值收束。

> 该流水线无单一公开"标准文档", 是综合媒体特稿惯例 + 网文创作论 + 编辑指南的工程化归纳; 建议 story-engine 将其做成可复用 prompt/模块并迭代。

## 四、时效性工程(定时采集 / 去重 / 聚类 / 衰减 / 入库)

### 4.1 采集与存储建议

- **入库: 建议入库(SQLite/Postgres 均可)**。原因: ① 话题聚类与热度衰减需要**历史快照对比**(同一词条跨多个采集周期的热度序列); ② 断网/超时可补采。
- **采集频率**: 热榜 5~10 分钟一变。**建议 10 分钟一轮**, 每个源一次 HTTP 请求, 存 `(source, word/title, hot_value/hotScore, timestamp, raw_json)`。
- **去重**: 以 `(source, 词条归一化)` 为唯一键, 同一词条只增热度序列、不重复存正文; 跨源用 **词条文本相似度(如 jieba 分词 + SimHash/向量)** 做合并。
- **话题聚类**: 把多源词条按文本相似度聚类成"事件", 用**出现源数(微博+知乎+抖音+百度都上榜=真爆点)** 和**热度加权和**排序, 过滤单源噪声。

### 4.2 热度衰减

- 抖音 `hot_value`、腾讯 `hotScore` 是**数值热度**, 可直接套 `score_decayed = hot_value * exp(-λ·Δt)` 做时间衰减, 用于"当前最热"与"趋势中"区分。
- 知乎 `detail_text`("3732 万热度")是文本, 需正则抽数值; `trend`/`debut` 字段给"上升/新上榜"信号。
- **趋势判断**: 连续两轮 `hot_value` 环比上升 = 上升期(适合做"正在发酵的议题"); 环比下降超过阈值 = 过气。

### 4.3 国内网络下的定时任务稳定性

- **单条 curl 直连实测稳定**: 百度/抖音/知乎/腾讯/B站 均 <300ms 返回, 适合 cron 轮询。
- **不稳定点**: ① 微博 403(用 NewsNow/RSSHub 兜底); ② github.com 直连超时(本环境实测 000, 装依赖需换源); ③ rsshub.app 被墙(用镜像/自建); ④ Tophub 慢(~8s, 需长超时)。
- **建议**: ① 每个源独立超时(快源 8s, 慢源 20s)+ 失败重试 1 次 + 失败不阻塞其他源; ② 用 `systemd timer` 或 Hermes cron 跑采集; ③ 采集结果先落库、后消费, 避免网络抖动丢失。
- **合规提示**: 各源为公开接口, 采集频率保持"10 分钟级"属正常浏览量级, 不要高频轰炸(尤其知乎/微博有风控); 内容用于创作转写, 不做原文复制分发。
