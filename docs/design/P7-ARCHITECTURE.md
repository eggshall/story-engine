# P7 总体架构与端到端流程（计划层主文档）

> 本文是**计划/架构**层文档：只回答"系统由什么组成、流程怎么走、谁在什么闸门做决策、每阶段拿什么验收"。
> 机制细节在子文档（`P7-LONG-MEMORY.md`），依据在 `docs/research/R1–R6`。**当前阶段不做实施。**
> 日期：2026-10-11（v2：并入 R5/R6 结论，闸门由 3 道改为 5 道）

---

## 0. 主目标与成功标准

**让一个人能长期、稳定、可追溯地写完一本超长篇**（几百万字起，架构上限 2000 万字），
且全书在**设定一致、文风统一、素材可溯源**三条线上不崩。AI 是可被约束的合著者，作者是唯一 canon 权威。

| # | 标准 | 判定 |
|---|---|---|
| S1 | 写到第 N 章，第 1 章的设定/伏笔仍被正确带入 | 抽检记忆层注入内容与正文一致性 |
| S2 | 第 N 章文风与作者指定参考文本集一致 | 漂移检测 + 作者盲评 |
| S3 | 每个非虚构素材细节都能追到来源 | 引用可回溯到素材卡片 |

---

## 1. 三条主线（系统只有三个记忆体）

| 主线 | 存什么 | 谁维护 |
|---|---|---|
| **素材线** | 题材无关的参考资料：古籍/方志、博物馆藏品与服饰器物、政体制度、地理气候、宗教神话、命名学、当下热点（"文献"只是它的一个特例） | 作者选源与红线，系统采集，AI 卡片化 |
| **记忆线** | 正文 + 分层摘要（章/组/卷/全书）+ 结构化状态（人物/地点/关系/时间线/伏笔） | 系统固化，作者审核 |
| **文风线** | 作者指定的参考文本集 + 文风画像 + 场景化锚点 + 漂移记录 | 作者定参考文本，系统量化与检测 |

三条线独立，只在两处交汇：**装配**（写前装上下文）与**校验**（写后查产出）。

## 2. 系统分层

```
          作者工作台（Vue）：素材库 · 设定集 · 大纲/节拍 · 章节编辑器 · 注入可见性面板 · 校验报告
                                     │  G0 G1 G2 G3 G4
   ┌─────────────────────────────────┴──────────────────────────────────────┐
   │ 流程编排层（FastAPI）：素材管线 · 固化管线 · 装配器 · 生成器 · 校验器 · 回写 │
   └──┬──────────────┬──────────────┬──────────────┬─────────────────────────┘
   ┌──▼───┐     ┌────▼────┐    ┌────▼────┐    ┌────▼─────┐
   │素材层 │     │ 记忆层   │    │ 文风层   │    │ 模型层    │
   │多源   │     │ 摘要树   │    │ 参考集   │    │ 本地(辅助)│
   │卡片   │     │ 状态机   │    │ 画像+锚点│    │ 远程(主笔)│
   │溯源   │     │ 索引     │    │ 漂移检测 │    │ 调用契约  │
   └───────┘     └─────────┘    └─────────┘    └──────────┘
```

分层原则（决定实施顺序）：① 模型层是地基（调用契约错则全线静默失败）；② 记忆层决定"能不能写下去"；
③ 素材线与文风线决定质量上限，可后置；④ 每层都是"结构化真相 + 可重建索引"，索引永不是权威。

## 3. 端到端流程（8 步 · 5 道闸门）

```
0 立项        作者定：题材/篇幅/基调/目标平台
1 素材采集    系统按 provider 拉多源资料（古籍库 / 博物馆开放数据 / 导入PDF / 网络热点）
              └ 采集前先过"来源白名单 + 许可 + 合规红线"三道过滤
2 素材编译    AI：资料 → 带来源的素材卡片（制度/服饰/地理/宗教/命名/事件/人物/议题）
══ G0 ══      作者审：设定集 + 参考文本集 + 素材取舍 + 敏感边界  → 冻结 canon 快照
3 大纲设计    作者定主线/卷/章（AI 只提候选）
══ G1 ══      作者审：三级大纲 + 伏笔埋放计划        ← 最贵返工点，必须逐章确认
4 场景/节拍   系统+AI 把章节展开为场景 beats（每 beat ≈ 300–500 字当量：POV/地点/目标/冲突/转折）
══ G2 ══      作者审：场景目标与转折  ← 正文前最后一道结构闸门，上下文最全、责任最重
5 装配+生成   系统按预算装上下文（素材卡片+记忆片段+文风锚点）→ 分段生成草稿
6 自动校验    三条线并行：素材溯源 / 设定自洽 / 文风漂移与 AI 味 → 校验报告（定位+建议）
══ G3 ══      作者审：批准 或 带指令重写（不是"是/否"，是"接受/带反馈重跑"）
7 canon 回写  作者决定"改正文还是改大纲"；摘要入库·状态更新·伏笔推进·设定改动向下传播
              └── G4 ── 回写需显式确认
   └──→ 回到 4（下一场景/下一章）
```

结构保证：**G0/G1 冻结后，后续所有章节共享同一份依据**；作者只在 5 个闸门决策，中间的采集/编译/装配/生成/校验全自动。

## 4. 人机分工

| 环节 | 作者 | AI/系统 |
|---|---|---|
| 素材范围与红线 | 决定要什么、不要什么、敏感边界 | 采集、去重、卡片化、溯源标注 |
| 参考文本集（"像谁"） | **指定**参考作品 | 提取画像与锚点、量化、漂移检测 |
| 设定 / 大纲 / 节拍 | 逐层审核并冻结 | 提候选、查冲突、保证后续一致 |
| 正文 | G3 审阅与改稿（改动的部分即 canon） | 装配、分段生成、定点重写 |
| 一致性 | 只裁决争议项（plot hole vs 刻意伏笔） | 全量自动校验 |
| 记忆 | 只审"待确认"队列 | 自动固化与回写 |

原则：AI 不得自行改写已冻结设定；不得综合外部资料发明 canon；只能按指令增量维护并标记待确认。

## 5. 五道闸门规范（"如何有效让 AI 介入"的核心）

| 闸门 | 输入 | 作者决策 | 输出（冻结物） | 验收 |
|---|---|---|---|---|
| **G0 设定** | 素材卡片集 + 设定/世界观草案 + 参考文本集候选 | 逐项确认或微调后批准；定敏感红线 | canon 快照 v1 + 参考文本集 | 主要实体设定全覆盖；每条素材有来源；参考文本已冻结 |
| **G1 总纲** | canon + 作者主线意图 | 审书→卷→章的走向，可重生成单章 | 三级大纲 + 伏笔台账 | 每章一句话走向清晰；每个伏笔有 plant/payoff 计划 |
| **G2 场景/节拍** | 已批准章节 + canon | 确认场景目标与转折；接受拆分建议 | 场景 beats（≈300–500 字/beat） | 每个 beat 有 POV/地点/目标/冲突/转折 |
| **G3 正文** | beats + 注入上下文 | 读审计标记 → 批准 或 带指令重写 | 定稿 | 严重校验项清零或明确豁免 |
| **G4 canon 回写** | 正文与大纲的偏离 | 决定改正文还是改大纲 | canon/大纲增量 | 回写后无"未确认的真相" |

### 5.1 闸门设计四铁律（跨工具/论文收敛，R6 §6.2）

1. **每层产出必须"可重生成 + 可带指令驳回"**：不满意就给指令重跑，闸门不是"是/否"。
2. **正文前必须保留场景/beat 层**：别让 AI 从章节大纲直接跳正文 —— 这是"正文自由发挥"的头号原因。
3. **审核通过的设定必须能可靠注入，且作者能看见注入了什么**（注入可见性）。"审过了但没注入"是隐性返工源。
4. **静态计划会衰减**：每段写作前基于大纲刷新本段计划，写后校验偏离，而非一次性喂入整本大纲。

## 6. 防返工机制（返工来源 → 架构对策，R6 §6.3）

| 返工源 | 架构对策 |
|---|---|
| 设定中途被迫改、污染前文 | G0 严审 + **设定版本快照/时间隔离**（变更只在生效章节之后生效，不直接改 canon） |
| 大纲层级缺失，正文自由发挥 | 强制 G2 场景/beat 层 |
| 计划跟随度随章节衰减 | 分段 re-plan + 写后查"大纲偏离" |
| 一致性错误向后传播 | 场景提交前校验 + 局部修补后才入记忆 |
| AI 味/文风漂移后期才处理 | 文风约束前置到生成 prompt（含禁词表），漂移检测常态化 |
| 上下文注入遗漏 | 注入可见性面板 + 常驻/触发开关 + 命中记录 |
| 长度/节奏失控 | 用**场景数量**控长度，不用字数参数 |

## 7. 素材线的现实约束（实测结论，决定 provider 选型）

### 7.1 直连可用性（2026-10 实测，裸连）

| 类别 | 可用 | 不可用/受限 |
|---|---|---|
| 中文古籍 | ctext.org 200、识典古籍 200、书格 200 | 维基文库超时、国家古籍资源库超时 |
| 热点源 | 百度热搜、知乎 v4、抖音、腾讯新闻、B 站（纯 JSON 无鉴权，<300ms） | 微博官方接口 403（走 NewsNow 演示 API 兜底）、Tophub/RSSHub 直连超时 |
| 模型/依赖 | registry.ollama.ai 200（embedding 模型可拉） | github.com 直连超时（需镜像） |
| 西方/多语言资料源 | 评估中（`R4b-western-sources.md`） | — |

### 7.2 许可分域（采集即标注）

公版原文（可自由改写）／开放许可 CC 数据与图像（多用需署名，商用条件要逐源确认）／需 key 的开放 API／
**受限整理本（如点校本）不可入库**。

### 7.3 合规红线（G0 闸门的硬检查项，R5 §2）

- **分水岭**：**借古喻今**（用结构类比现实议题）可用；**借古讽今**（讽刺批判现实）高危。有判例。
- **换名影射不豁免**：改朝代/改地名/用 Z 国 T 岛这类代称仍属违规。
- **历史题材具体禁忌清单**（公开编辑指南 + 总局内部分享口径）：涉及民族称谓、疆域扩张、镇压起义类人物、
  美化民国/北洋、近现代政治事件与人物等，均属高危 → 采集与设定阶段即过滤。
- **安全区**：民生/经济/科技/职场这类议题的**结构性类比**，且落脚正面价值。
- **执行后果是频道/栏目级**，不只在单本书 —— 因此合规必须在 G0 一次做对，而不是逐章补救。
- 热点素材的流水线：多源采集 → 抽"议题+冲突双方+争议点" → **议题分级过滤** → 结构类比映射（不做人物/政权影射）→ 冲突设计 → 正面价值收束。

## 8. 分期计划（阶段目标 + 可验证结果）

| 阶段 | 目标 | 可验证结果 | 依赖 |
|---|---|---|---|
| **Ⅰ 地基** | 模型调用契约与最小闭环可靠 | 写作链路不再返回空正文；每次生成能给出"注入了什么"；装配→生成→校验跑通 | 已实测，待落地 |
| **Ⅱ 记忆** | 写下去不靠人脑回忆 | 20M 字级装配输入受限在预算内；第 N 章能接续第 N−100 章主线 | Ⅰ |
| **Ⅲ 设定库** | 设定成为可查询、可演化的权威源 | 伏笔可追踪到状态；悬空伏笔/设定冲突可报出 | Ⅱ |
| **Ⅳ 素材线** | 资料可采集、编译、溯源 | 素材卡片带来源与许可；产出中细节可回溯；参考文本集可复现文风 | R4/R4b/R5 |
| **Ⅴ 闸门与文风闭环** | G0–G4 在界面上可用，文风自动保障 | 五道闸门可审可回退；漂移与 AI 味在生产链路常态化 | Ⅲ/Ⅳ |
| **Ⅵ 质量上限** | 提升"像人写的"与效率 | 按需：rerank、图谱关系、风格微调 | Ⅴ |

顺序理由：Ⅰ/Ⅱ 决定"能不能"，Ⅲ–Ⅴ 决定"稳不稳"，Ⅵ 决定"好不好"。先跑通最小闭环，再逐层加记忆、素材与闸门。

## 9. 需要作者先拍板的前置决策

1. **参考文本集策略**：每本书指定 3–5 部参考作品，还是继承全局文风库？
2. **素材来源范围与许可红线**：允许多源网络采集，还是只吃"作者导入 + 公版/开放许可"？
3. **题材映射现实的深度**：借古喻今的安全区怎么划（这直接决定 G0 的过滤规则）。
4. **模型分工**：正文全远程，还是"本地草稿 + 远程精修"。
5. **目标平台**：决定章节长度、节奏与敏感词策略。

## 10. 风险与不做

| 风险 | 对策 |
|---|---|
| 模型静默产空（思考模式吃预算、温度失效） | 调用契约在模型层统一强制；空产出即失败重试 |
| 早期设定未冻结导致后期大改 | G0/G1 冻结 + 设定版本快照与向下传播 |
| 素材无溯源导致"编造史实" | 采集即带来源，校验做"无卡即标记" |
| 合规踩线导致栏目级后果 | G0 一次做对；采集与设定双重过滤 |
| 记忆膨胀拖慢生成 | 装配预算硬上限，绝不塞全文 |
| 双写不一致 | 结构化真相唯一权威，索引可重建 |

**不做**：把全文塞进上下文；对全文建知识图谱；追求"AI 自己写完整本书"；用 AI 替代作者的 canon 决策。
