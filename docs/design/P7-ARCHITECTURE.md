# P7 总体架构与端到端流程（计划层主文档）

> 计划/架构层文档，不做实施。机制细节见 `P7-LONG-MEMORY.md`，调研依据见 `docs/research/R1–R6`。
> 日期：2026-10-11（v3：按作者实际写法重构 —— 作者主写、AI 辅助、素材持续流入、参考书目供技法）

---

## 0. 主目标与作者的实际写法（架构必须匹配的前提）

**目标**：让作者本人能长期、稳定、可追溯地写完一本超长篇（几百万字起，架构上限 2000 万字），
全书在**设定一致、文风统一、素材可溯源**三条线上不崩。

架构须匹配的四条实际前提（v3 修正）：

| # | 作者的实际写法 | 架构含义 |
|---|---|---|
| P1 | **正文由作者自己写** | 系统是"写作工作站 + 辅助"，不是自动写作机；AI 的默认姿态是辅助介入，不是整章代笔 |
| P2 | **文风参考的是"书目"** —— 借鉴的是写作分割与技巧，不是整本模仿一个风格 | 文风线升级为**参考书目技法库**：技法条目 + 分割方式 + 风格特征，按需取用、可多本组合 |
| P3 | **素材先搜索，也会随书写补充、实时导入** | 素材线是**持续流入的流**，不是"采集完就冻结的阶段"；卡片随时新增，变更需隔离以不污染前文 |
| P4 | **题材不受限，内容由作者把关** | 系统不设题材过滤与红线规则；只保留最小限度的"来源标签"（便于溯源，不做拦截） |

成功标准：S1 写到第 N 章仍能正确带入第 1 章的设定/伏笔；S2 第 N 章文风与作者参考书目一致；S3 素材细节可回溯到来源。

## 1. 三条主线（系统只有三个记忆体）

| 主线 | 存什么 | 形态 | 谁维护 |
|---|---|---|---|
| **素材线** | 题材无关的参考资料：古籍/方志、博物馆藏品与服饰器物、政体制度、地理气候、宗教神话、命名、热点…（"文献"是其中一个特例） | **持续流入**：初始搜索 + 边写边补 + 实时导入 | 作者选源与导入，系统卡片化与溯源 |
| **记忆线** | 正文 + 分层摘要（章/组/卷/全书）+ 结构化状态（人物/地点/关系/时间线/伏笔） | 随写作增量固化 | 系统固化，作者审核 |
| **技法线**（原"文风线"） | 参考书目 → **技法条目**（手法/节奏/信息释放/视角调度）+ **分割方式**（段落·场景·章节的切法）+ 风格量化 | 书目级 + 场景级按需取用 | 作者指定书目，系统抽取与提示 |

三条线独立，只在两处交汇：**装配**（写前把相关片段与技法提示放到手边）与**校验**（写后查一致性）。

## 2. 系统分层

```
      作者工作台（Vue）：写作编辑器 · 素材库/导入 · 设定集 · 大纲/节拍 · 技法面板 · 校验报告 · 注入可见性
                                    │  闸门 + 随时调用 AI
   ┌────────────────────────────────┴───────────────────────────────────────┐
   │ 流程编排层（FastAPI）：素材管线 · 固化管线 · 装配器 · 辅助生成器 · 校验器 · 回写 │
   └──┬──────────────┬──────────────┬──────────────┬─────────────────────────┘
   ┌──▼───┐     ┌────▼────┐    ┌────▼────┐    ┌────▼─────┐
   │素材层 │     │ 记忆层   │    │ 技法层   │    │ 模型层    │
   │卡片   │     │ 摘要树   │    │ 技法条目 │    │ 本地(辅助)│
   │溯源   │     │ 状态机   │    │ 分割方式 │    │ 远程(主力)│
   │增量   │     │ 索引     │    │ 风格特征 │    │ 调用契约  │
   └───────┘     └─────────┘    └─────────┘    └──────────┘
```

分层原则：① 模型层是地基（调用契约错则全线静默失败）；② 记忆层决定"能不能长期写下去"；
③ 素材层与技法层决定质量与手感，可逐步补强；④ 每层都是"结构化真相 + 可重建索引"，索引永不是权威。

## 3. 端到端流程（两条并行流 + 一个写作循环）

```
【素材流 · 持续】  搜索/导入 → 卡片化（带来源）→ 素材库（随时新增/修订，不冻结）
                                                          │
【技法流 · 一次建库, 随时取用】 参考书目 → 拆技法/分割 → 技法库（按场景检索提示）
                                                          │
                    ┌─────────────────────────────────────┘
                    ▼
【写作循环 · 作者主写】
  A 装配      系统把"本章节拍 + 本场相关的素材卡片 + 记忆片段(状态/伏笔/前文摘要) + 技法提示"放到手边
  B 作者写    作者写正文；随时调用 AI 辅助（见 §4 辅助动作表）
  C 校验      三条线并行查：素材溯源（写了未建档的细节）/ 设定一致（状态·时间线·伏笔·称谓）/ 技法与文风（漂移·AI 味·禁词）
  D 回写      定稿后固化：摘要入库 · 状态更新 · 伏笔推进 · 新增素材卡片补档 · 文风指标留痕
  └──→ 回到 A 写下一场
```

### 3.1 闸门（因为作者主写，闸门减少为 3 道）

| 闸门 | 时机 | 作者决策 | 产出 |
|---|---|---|---|
| **G0 设定与技法** | 开书前 | 定设定集；指定参考书目（每本注明"提供什么"） | canon 快照 v1 + 参考书目清单 + 技法库 v1 |
| **G1 大纲** | 开书前 + 卷末 | 审书→卷→章节拍（AI 只提候选） | 三级大纲 + 伏笔台账；节拍可随写调整 |
| **G2 定稿（逐场/逐章）** | 每场写完 | 采纳/驳回校验报告，决定"改正文还是改设定" | 定稿 + canon 增量 |

> 原 G2 场景闸门、G3 正文闸门合并为 G2 定稿闸门：**因为正文是作者写的，"审 AI 草稿"这个环节天然消失**；
> 但 beat 层仍保留 —— 它现在是"作者写之前的节拍备忘 + AI 辅助的落点"，而不是审核对象。

### 3.2 两条流与循环的耦合点

- 素材流 → 装配：命中的卡片随场景注入（写服饰场景就取服饰卡片）；
- 技法流 → 装配：按当前场景类型给技法宝典（这一场要写对峙 → 取"以静写动""对白留白"这类条目）；
- 循环 → 素材流：写作中冒出的新设定/新名词 → 未建档提醒 → 一键补卡片（这就是"边写边补素材"）；
- 循环 → 记忆线：定稿即固化，下一场自动带上最新状态。

## 4. 人机分工（作者主写，AI 辅助介入）

| 环节 | 作者 | AI 的辅助动作 |
|---|---|---|
| 素材 | 搜索、导入、决定用不用 | 卡片化、去重、标注来源、按场景召回、**写了未建档时提醒** |
| 参考书目 | 指定书目并注明"提供什么" | 抽技法条目与分割方式、量化风格、供场景提示 |
| 设定/大纲 | 审核冻结 | 提候选、查冲突、保证前后一致 |
| **正文** | **自己写** | ① 续写/扩写（在光标处接写）② 改写润色（保住原意的重写）③ 场景起手/收尾候选项 ④ 对白打磨 ⑤ 卡文时的分支建议 |
| 校验 | 只裁决争议项 | 全量自动查：素材溯源、设定一致、技法与文风漂移、AI 味 |
| 记忆 | 只审"待确认" | 自动固化摘要与状态、伏笔推进、变更隔离 |

原则：**AI 不擅自改已定稿正文；不把未确认内容写入 canon；不替作者决定剧情走向，只给可选项。**

## 5. 三条线的关键机制（计划层要求，细节见子文档）

### 5.1 记忆线
分层摘要（章→组→卷→全书）+ 结构化状态（人物/关系/地点/时间线/伏笔状态机）+ 检索注入；
装配有**硬预算上限**，常驻骨架 + 按需检索，绝不塞全文。验收：20M 字级装配输入受限；第 N 章能接续第 N−100 章主线。

### 5.2 技法线（参考书目 → 技法）
- 参考书目每本产出三样东西：**技法条目**（可复用的写作手法）、**分割方式**（段落/场景/章节怎么切）、**风格特征**（量化 + 样段）。
- 技法条目带**适用条件**（"对峙场景""结尾收束"），写作时按场景检索提示，而不是锁死一个风格。
- 多本书目可组合：作者可按场景指派（战斗场参考 A，抒情场参考 B）。
- 验收：给定场景类型能取回对应技法条目；文风漂移检测与 AI 味拦截常态化。
- **与"作者导入的写作理念/方法论"分开处理**：从书目抽取的技法是"模仿型"（像谁写，靠样本示范）；
  作者导入的培训材料/方法论是"规范型"（该怎么写，能否判定），走 §5.5 的规则库路径。

### 5.3 素材线（持续流入）
- 采集方式：① 初始搜索；② 写作中实时导入（粘贴/文件/网页）；③ 未建档提醒反向补档。
- 每张卡片带**来源标签**（哪里来的、何时入库、可信度）。系统不做题材判定与拦截 —— 内容由作者把关（P4）。
- 卡片"变更需隔离"：修订不覆盖历史版本，只在生效点之后影响后续章节，避免改设定污染已写正文。
- 验收：产出中每个非虚构细节能追到卡片来源；改素材不影响已定稿章节。

### 5.4 素材源的现实约束（实测白名单 → 决定"系统能替你搜什么"）

实测（2026-10，裸连）得出**两条采集路径必须分开**的规则：

- **系统自动采集只走"裸连白名单"**（实测返回 200 的源）；
- **白名单外的资料走"作者导入"路径**（浏览器能开、命令行打不开的源，以及订阅/付费库），
  系统只负责卡片化与溯源 —— 这也正好对应作者"边写边补、实时导入"的实际写法。

| 域 | 系统可自动采集（实测可用） | 需申请 key | 裸连不可用 → 走作者导入 |
|---|---|---|---|
| 中文古籍 | ctext.org、识典古籍、书格 | — | 维基文库、国家古籍资源库 |
| 西方器物/服饰 | **Met Open Access（CC0，服饰学院 31,897 件 / 兵器盔甲）**、Rijksmuseum 新 API（免 key）、V&A、Cleveland（CC0）、FIT 服饰史、KCI | Smithsonian、Europeana | Walters、Getty API、Museum of London、**Wikimedia 全系** |
| 文本库 | Gutenberg + Gutendex、Standard Ebooks、Perseus、Sacred Texts | — | Internet Archive、Open Library、Wikisource |
| 政体/制度 | Constitute（条款禁商用）、Comparative Constitutions | — | — |
| 地理/气候 | WorldClim | — | Natural Earth、GeoNames、OpenStreetMap |
| 命名学 | ONS（英国，OGL） | — | census.gov / ssa.gov（反爬拦截，浏览器可下）、Behind the Name（词义禁止抓取） |
| 时效/热点 | 百度热搜、知乎 v4、抖音、腾讯、B 站 | — | 微博（403，走 NewsNow 兜底）、Tophub/RSSHub |

工程注意：**外部端点会变更或被弃用**（实测 Met 的 search 端点已 410、Rijksmuseum 旧 API 已 410）
→ 采集层要把失效源标灰降级，不能因单一源挂掉拖垮整条采集。

**许可标签三档（只标注，不拦截 —— 与 P4 一致）**：
① 可直接用（公版文本、CC0 图像与元数据、美国政府公有领域统计）；
② 只可参考改写（CC BY-NC-SA 如历史地图库、条款禁商用的文本库、受限词条与译文、逐件看 rights 的预览图）；
③ 不入库（受限整理本，如点校本）。
每张卡片记 `来源 URL + 许可标签 + 入库时间`，供作者自查（系统不代做判断）。

**设定卡片模板已就绪**：`R4b §B` 给出五张字段表 —— 服饰/器物、政体/制度、地理/气候/物产、宗教/神话、命名；
字段分"事实字段"（来自资料，抄录/翻译）与"设定字段"（世界观内的决定，标注已定/待定）。

### 5.5 理念/规则库（作者导入的写作方法论）

作者会导入自己的写作理念与培训材料（如平台的写作培训体系、编辑经验、自己的写作原则）。
**关键：它不是"塞给 AI 的文档"。** 整篇丢进 prompt 在三处失效 —— 每次生成都占预算、注意力被稀释
（长上下文掉性能有实证）、而且"材料在上下文里"不等于"条款生效"。正确做法是**编译成条款**：

```
作者导入材料（培训内容 / 编辑经验 / 平台规范 / 自己的写作原则）
   ↓ 抽取（去重、去掉无法判定的口号）
条款库：规则名 + 触发场景 + 判定方式 + 违反时怎么办 + 来源与启停
   ↓ 分类绑定
A 可自动检验 → 写后校验清单（硬告警）+ 写前提示
B 半可检验   → LLM 当判官的校验项（结构化输出 + 定位）
C 只能做提示 → 场景化取用（写作时作为参考出现，不做判定）
```

| 类别 | 判定方式 | 典型条款（完整样例见 R7） | 系统归属 |
|---|---|---|---|
| A 可自动检验 | 正则/统计/确定性规则 | 章末是否有钩子、开篇 N 字内是否出冲突、视角是否一致、禁词表、段落长度、伏笔是否回收 | 校验器（硬告警）+ 写前提示 |
| B 半可检验 | LLM 当判官，结构化输出 | 信息释放是否过快、人物动机是否充分、场景目标是否达成 | 校验项（含定位与建议） |
| C 只能做提示 | 不可判定 | 文笔层次、情感张力 | 仅作写作时的参考提示 |

三条设计原则：
1. **条款必须可执行**：不能判定的"原则"等于没有；判不了的一律降级为 C 类提示，不做伪精确判定。
2. **条款要绑定场景与粒度**：同一条规则可能只适用于"开篇章""章末""战斗场"。
3. **条款可溯源、可单独停用**：每条注明来自哪份材料（作者自有材料，仅本地留存），可逐条开关。

验收：导入一份方法论后能产出一批带分类的条款，并在写作/校验时能看到"这一条被触发"的具体位置。

## 6. 防返工机制（改动成本前置消化）

| 返工源 | 架构对策 |
|---|---|
| 设定中途要改、污染前文 | 设定/素材版本快照 + 生效点隔离（改旧不改前） |
| 大纲缺失导致写飞 | G1 大纲 + 章节节奏备忘（beat 备忘录，非审核对象） |
| 写到后面忘了前面写过什么 | 记忆线自动固化 + 装配必带相关状态与伏笔 |
| 一致性错误累积 | G2 定稿前校验 + 争议项交作者裁决 |
| 文风/技法走失 | 技法提示按场景给出 + 漂移与 AI 味告警 |
| 素材散落各处找不回 | 采集即建档 + 场景召回 + 未建档提醒 |
| 反复重写大段 | 校验只标问题与定位 + 定点重写（不整章重写） |

## 7. 分期计划（能不能 → 稳不稳 → 好不好）

| 阶段 | 目标 | 可验证结果 |
|---|---|---|
| **Ⅰ 地基** | 调用契约与最小闭环可靠 | 不再静默产出空正文；每次生成能回答"这次带了什么进来"；装配→辅助→校验跑通 |
| **Ⅱ 记忆** | 长期写作不靠人脑回忆 | 装配输入受限在预算内；第 N 章正确接续第 N−100 章主线与伏笔 |
| **Ⅲ 设定库** | 设定成为可查询、可演化、可隔离变更的权威源 | 伏笔可追踪；悬空伏笔/设定冲突可报出；改设定不污染已定稿 |
| **Ⅳ 技法线** | 参考书目可用起来 | 书目 → 技法条目/分割方式/风格特征；按场景取回技法提示 |
| **Ⅴ 素材线** | 资料随写随补、可溯源 | 三种采集路径可用；细节可回溯；未建档提醒生效 |
| **Ⅵ 质量上限** | 提升手感与效率 | 按需：rerank、图谱关系、书目风格微调 |

## 8. 已定决策（作者已确认 · 锁定为实施约束）

| # | 决策 | 锁定的行为约束 |
|---|---|---|
| D1 | **AI 默认姿态 = 光标处续写/扩写**；"整场草稿"是显式选项 | 辅助入口默认按选区/光标上下文工作；整场草稿必须由作者主动触发，不做默认行为 |
| D2 | **参考书目每本一句话注明"提供什么"** | 书目录入时含"提供什么"字段（技法/分割/语感），系统抽取以该标注为约束方向，不自由发挥 |
| D3 | **素材未建档即提醒，但不拦写作** | 提醒是异步的（侧栏/行内标记），可出现"稍后再建档"；不阻塞输入、不弹模态框 |
| D4 | **AI 辅助全走远程**；本地只做离线活 | 续写/改写/校验等交互动作走远程；卡片化、摘要、量化指标等批量离线任务走本地模型 |

D4 的附加约束（由实测得出）：本地 `gm4` 占显存约 14.4GB，与本地写作并存会挤爆 16GB 显存 →
**离线批量任务与交互式写作必须串行排队**，不能并发。

## 9. 风险与不做

| 风险 | 对策 |
|---|---|
| 模型静默产空（思考模式吃预算、温度失效） | 调用契约在模型层统一强制；空产出即失败重试 |
| 记忆膨胀拖慢每次生成 | 装配预算硬上限，绝不塞全文 |
| 素材膨胀找不回 | 场景召回 + 来源标签 + 未建档提醒 |
| 改设定污染前文 | 版本快照 + 生效点隔离 |
| 双写不一致 | 结构化真相唯一权威，索引可重建 |

**不做**：把全文塞进上下文；对全文建知识图谱；让 AI 代笔整本书；替作者决定剧情；替作者判断题材内容。
